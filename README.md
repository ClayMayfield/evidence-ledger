# Evidence Ledger — research prototype

This is a work in progress; the competition entry has not yet been submitted. Its purpose is to explore a review workflow that separates a chart, user-confirmed observations and an explicitly structured numeric claim. An optional on-device model can propose structured fields from a statement, but the proposal is fallible and must be checked by the user; the program checks only the structured fields. It does not verify a chart's underlying data or establish that any claim is true beyond the confirmed observations.

## Hosted demo and current verification

The current public review page is [Evidence Ledger](https://hybrid-ai-exploration.web.app/); its separate [cloud page](https://hybrid-ai-evidence-cloud.web.app/ledger-cloud) offers optional explanation and chart reading. Use synthetic, non-sensitive data only: the privacy boundary has not been fully audited and image metadata may be included when an image is sent to Google.

On November 24, the hosted review page loaded its synthetic example. In the in-app browser, `Box A | 8 | kg` was manually entered and confirmed, then checked against the structured claim `Box A | 8 | g`; the page displayed **INCONSISTENT**. The same browser passed the textual result to the separate cloud page, where an explicit request received an explanation. In a separate user-authorized request on the hosted cloud page, the synthetic chart was sent to Google and the suggestions matched Box A 8 kg and Box B 12 kg. The hosted cloud app has a registered App Check provider; these limited successful requests do not establish general model accuracy, a privacy guarantee, or uninterrupted availability throughout judging.

On November 24, the hosted review page was also tested in desktop Chrome with the on-device model available: it proposed Box A 8 kg and Box B 12 kg for the built-in synthetic chart. This is one sample on one device, not evidence of general accuracy or availability on judges' devices. The in-app browser separately reported that its local LanguageModel API was unavailable. A single-browser workflow combining hosted device inference with cloud explanation remains unverified. When device reading is unavailable, the cloud chart reader is a **manual** fallback: choose and send an image explicitly, check the result, and enter the observations yourself. Contest eligibility and judging outcomes are not established by these tests.

On November 22, a real device-model request through this prototype in desktop Chrome identified both labels, values and units in its clear synthetic chart. After revising the number parser, a second device request in Chrome populated both values correctly. The reviewed 8 kg observation and structured 8 g claim produced an inconsistent result; the same browser opened a cloud preview showing the text evidence, without calling a cloud model. This single sample does not measure accuracy, and the full device-to-cloud workflow has not been verified.

Run `npm ci --ignore-scripts` in this directory. Then run `node server.mjs` and `node cloud-server.mjs` in two separate terminals, leaving both running, and open `http://127.0.0.1:43127/`; run the bounded checks with `node --test core.test.mjs csv.test.mjs suggestions.test.mjs claim-draft.test.mjs build-staging.test.mjs selection-race.test.mjs cloud-chart.test.mjs`. The servers bind only to localhost. The separate cloud preview is served at `http://127.0.0.1:43123/ledger-cloud`, using a separate local origin; if another process already uses that port, stop only the known test service before starting this one. The prototype accepts PNG and JPEG images up to 4 MB and, after decoding, up to 12 megapixels. Use only non-sensitive data: the privacy boundary has not been fully audited, and image metadata is not stripped. In the in-app browser a synthetic PNG could be selected and reselected, retained observations required confirmation, an old verdict was cleared, and a corrupt image was rejected. Other formats and image dimensions still require verification. It uses the Firebase Web SDK 13.3.0 from Google's CDN and a placeholder project for the device experiment. Chrome, its on-device model and suitable feature configuration are necessary for device suggestions. The model's text is displayed and its suggestions require human verification. The optional statement-to-fields feature initially failed on a synthetic sentence; after prompt and label checks were revised, two simple synthetic sentences produced correct editable fields in desktop Chrome with a real on-device model. These examples do not establish general accuracy or semantic correctness. The separate local cloud page displays the evidence before an explicit send; its cloud call requires a user-supplied Firebase configuration and an App Check token registered for that page's origin. On November 23, the local cloud page sent synthetic text to the cloud model and displayed a response in the in-app browser, reusing its previously registered debug token; no chart image was included. This local test was separate from device inference in desktop Chrome.

The optional CSV reader uses Papa Parse 5.5.3, Copyright (c) 2015 Matthew Holt, and exact decimal comparisons use decimal.js 10.6.0, Copyright (c) 2025 Michael Mclaughlin; both use MIT licenses preserved in `LICENSES`. See `THIRD_PARTY_NOTICES.md` for pre-existing dependencies. Numeric inputs are limited to 100 digits and exponents between -1000 and 1000; values outside the supported range are not checked. The suggestions parser preserves JSON number tokens as text before they can be rounded by JavaScript; this revision has program tests and was retested in Chrome with one synthetic chart. Labels match exactly. Explicit units such as `visitors` or `USD` compare only when their spelling and case match; only `g` and `kg` are converted. An empty unit means unknown, not unitless; write `unitless` explicitly for quantities without units. Neither input source is treated as ground truth.

The page's restrictive CSP and API checks are experimental safeguards, not a guarantee of privacy or an audited sandbox. In a separate synthetic browser fault-injection test the SDK attempted a cloud request when the device API was absent despite ONLY_ON_DEVICE; CSP blocked that test connection. The output `inferenceSource` only describes a completed response, and cannot prevent data transmission. Recheck this risk and all network paths before allowing real inputs. Do not add debug tokens or project secrets to files or a repository.

## Experimental hosted staging

`node build-staging.mjs release.example.json` generates a local `.staging-*` directory using synthetic, nonfunctional values. It creates separate `review` and `cloud` targets and a Firebase Hosting configuration; the hosted cloud entry uses reCAPTCHA Enterprise and does not contain the local debug-token switch. For a later real staging build, provide a separate private JSON file following the example with two distinct HTTPS origins, a reCAPTCHA Enterprise site key and a **non-production demonstration** Firebase web configuration. The resulting cloud runtime is public when hosted; never put secrets, production API keys or personal data into it. The generated directory is ignored by Git and must not be committed. No resources or deployment are created by this script.

For a new deployment, register the cloud domain with App Check, verify reCAPTCHA and service quota, bind the Hosting targets, test both CSPs and cross-window messaging in actual browsers, and verify device-unavailable and initialization-failure paths with synthetic inputs. The hosted instance has registered App Check and passed the limited text and image requests described above, but these checks remain incomplete for the overall hosted build. In particular, separate origins and CSP are not a complete privacy guarantee. Free access and available quota through the end of judging have not been established.

Prior art includes EmphasisChecker (chart/caption emphasis), ChartCheck (claim verification), and Olli (accessible structured chart navigation). The proposed combination of user-confirmed observations, explicit claim structure, deterministic comparison and opt-in cloud explanation is a working hypothesis, not a claim of novelty or proven user value. Any third-party code incorporated later must retain its license and attribution and be disclosed to the contest.


## Experimental opt-in cloud chart reader

The separate cloud page offers a manual fallback when device inference is unavailable. It can generate the same synthetic chart locally or preview a user-selected PNG/JPEG (up to 4 MB and 12 megapixels). Selecting or generating an image does not send it; the user must explicitly choose to send the selected image to Google. The model response is unverified and must be reviewed against the chart; the user can then enter observations manually on the review page. Image metadata may be included in uploaded files, and this experimental flow is only for synthetic, non-sensitive inputs.

On November 24, with the participant's authorization, the in-app browser sent the synthetic sample to Google using the local cloud reader and its existing App Check debug configuration. The cloud response suggested Box A as 8 kg and Box B as 12 kg, matching that sample. The hosted cloud reader was later tested separately with the same synthetic example, as described above. These limited examples do not establish general accuracy; users must check each suggestion. Selection and race cases also have mock tests. The hosted device-to-cloud workflow in one browser remains unverified, and the fallback is manual rather than automatic.
